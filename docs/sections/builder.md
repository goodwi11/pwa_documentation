# Конструктор

Конструктор — это основной инструмент для создания и редактирования PWA-приложений. Он состоит из шести вкладок, которые проходятся последовательно:<br>
1. [Основное](builder.md#main)<br>
2. [Контент](builder.md#content)<br>
3. [Пуши](builder.md#push)<br>
4. [Аналитика](builder.md#analitycs)<br>
5. [Клоакинг](builder.md#cloaking)<br>
6. [Домен](builder.md#domain)

## Основное {#main}

На данном этапе настраиваются базовые параметры приложения.

**Шаг 1.** **Название**

Введите название вашего PWA. Это имя будет отображаться на главном экране устройства пользователя и в самом приложении.

**Шаг 2.** **Язык**

Выберите язык интерфейса приложения из выпадающего списка.

**Шаг 3.** **Ссылка на оффер**

Укажите URL вашего оффера — это адрес, на который будут попадать пользователи из PWA, вводите полную ссылку. (например: <https://exampleoffer.com>)

!!! note "Примечание"
    При необходимости, вы можете включить поддержку загрузочной страницы для устройств на операционной системе iOS. По умолчанию она всегда включена. 

**Шаг 4.** **Способ создания**

Доступно два варианта:

1. **Создать на основе приложения** — парсинг данных из Google Play. Выберите этот вариант, если хотите создать PWA на основе существующего приложения из магазина приложений. Система автоматически подтянет:
- Название и иконку<br>
- Скриншоты<br>
- Описание<br>
- Рейтинг и количество скачиваний<br>
- Информацию о разработчике

Вставьте полную ссылку на приложение из Google Play в формате: <https://play.google.com/store/apps/details?id=org.telegram.messenger>

2. **Создать из своего дизайна** — ручная настройка. Выберите, если хотите загрузить собственные креативы и полностью кастомизировать приложение.

## Контент {#content}

На данном этапе настраивается весь контент, который увидят пользователи в вашем PWA. Справа отображается превью приложения в реальном времени.

!!! note "Примечание"
    Вместо ручного ввода данных, вы можете сгенерировать контент используя соответствующую кнопку (✨) рядом с полем ввода.

### Шапка приложения {#header}

| Поле | Описание |
|------|----------|
| Иконка | Загрузите иконку приложения |
| Название | Укажите название приложения для отображения в шапке |
| Автор | Укажите имя разработчика/издателя |
| Рейтинг | Укажите среднюю оценку приложения |
| Размер | Укажите размер приложения в МБ |
| Возраст | Укажите возрастное ограничение |
| Версия | Укажите номер версии |
| Скачиваний | Укажите количество установок |
| Отзывов | Укажите количество отзывов |

### Скриншоты {#screen}

Загрузите скриншоты приложения — они будут отображаться в карусели на странице установки. 

- Поддерживаемые форматы: JPEG, PNG
- Рекомендуемое соотношение сторон: 9:16 (вертикальные) или 16:9 (горизонтальные)
- Используйте минимум 4 скриншота

Нажмите кнопку **«Добавить скриншоты +»** чтобы загрузить дополнительные изображения.

### Видео {#video}

Опционально можно добавить ссылку на YouTube-видео с обзором или трейлером приложения. Вставьте полную ссылку в формате: <https://www.youtube.com/watch?v=XXXXXX>

### Описание и тэги {#descript_tags}

**Шаг 1. Описание**<br>
Укажите текстовое описание приложения. Поддерживает несколько абзацев. Опишите функционал и преимущества — это влияет на конверсию в установку и общее восприятие PWA.

**Шаг 2. Тэги**<br>	
Укажите ключевые слова через запятую, например: *game*, *football*, *basketball*.<br>
Тэги отображаются как метки под описанием.

### Оценки и рейтинг {#rating}

Настройте распределение оценок по звёздам. Используйте слайдеры для указания количества отзывов с каждой оценкой.<br>
Опция **«Связать оценки с количеством отзывов»** автоматически пересчитает распределение, чтобы сумма соответствовала указанному общему количеству отзывов.

### Отзывы и ответы {#reviews}

Создайте реалистичные отзывы для повышения доверия:

| Поле | Описание |
|------|----------|
| Фото | Аватар автора отзыва |
| Автор | Имя/никнейм пользователя |
| Рейтинг | Оценка от 1 до 5 звёзд |
| Отзыв | Текст отзыва пользователя |
| Ответ | Текст ответа разработчика |

Нажмите **«Добавить отзыв +»** для добавления нескольких отзывов.

### Контакты разработчика {#contacts}

Укажите контактные данные для раздела «О разработчике»:<br>
- **Адрес** — юридический или физический адрес<br>
- **Электронная почта** — email для связи

После заполнения всех полей нажмите **«Сохранить»** для сохранения указанного контента.

## Пуши {#push}

На данном этапе вы выбираете, какие push-уведомления будут привязаны к создаваемому PWA.

!!! warning "Внимание" 
     При первом создании PWA список будет пустым. Необходимо создать пуш-уведомления в разделе **«Пуши»** бокового меню (см. подробнее в разделе [Push-уведомления](push.md))

**Как это работает:**

- Создайте нужные пуш-уведомления в разделе **«Пуши»**
- Затем при создании или редактировании PWA выберите нужные пуши из списка
- Выбранные пуши будут отправляться пользователям этого конкретного приложения

**Добавление пушей:**

**Шаг 1.** Нажмите **«+ Добавить пуш»** для добавления слота<br>
**Шаг 2.** Выберите нужный пуш из выпадающего списка (например «Push 1», «Push 2»<br>
**Шаг 3.** Добавьте несколько пушей при необходимости<br>
**Шаг 4.** Для удаления нажмите иконку корзины (🗑️) рядом с пушем

!!! note "Примечание"
    Справа отображается превью — так пуш будет выглядеть на устройстве пользователя.

## Аналитика {#analitycs}

При необходимости, на данном этапе вы можете настроить постбеки и подключить пиксель.

### Входящие постбеки {#incoming_postbacks}

При помощи них партнёрская сеть сообщает нам о результате трафика. Вы **вставляете нашу ссылку** в настройки постбека на стороне оффера/CPA-сети.

#### Ссылка для партнерской сети или трекера

Пример: <https://domain.com/event?click_id={click_id}&status=Lead&cost={payout}>

- `domain.com` — домен вашего PWA (по нему мы определяем, к какому PWA принадлежит конверсия).
- `{click_id}` и `{payout}` — **макросы партнёркской сети или трекера**: параметр  `click_id` и сумма выплат будет подставлена автоматически. Название макросов могут отличаться (`{click_id}`, `{subid}`, `{payout}`, `{amount}` и т.п.) — смотрите документацию вашей партнёрской сети или трекера.

#### Параметры

| Параметр | Обязательный | Описание |
|---|:---:|---|
| `click_id` | ✅ | Наш идентификатор клика. По нему конверсия сопоставляется с исходным показом (`Visit`). |
| `status` | ✅ | Тип конверсии: `Lead` \| `Sale` \| `Reject` \| `Rebill`. |
| `cost` | ❌ | Сумма конверсии (payout). По умолчанию `0`. Наполняет метрики выручки/профита. |
| `account_id` | ❌ | UUID аккаунта. Если не передан — восстановим из `Visit` по `click_id`. |
| `pwa_id` | ❌ | UUID PWA. Если не передан — определим по домену, на который пришёл `/event`. |
| `любые дополнительные параметры` | ❌ | Все прочие query-параметры (`sub1`, `txid` и т.п.) **пробрасываются** в вашу отбивку. |

!!! note "Примечание"
    Вместо `status` также принимаются устаревшие `event` и `event_type`.

#### Статусы конверсий

- `Lead` — лид (регистрация/заявка).
- `Sale` — продажа/депозит.
- `Reject` — отклонённая конверсия.
- `Rebill` — повторное списание.

#### Ответы

| Код | Тело | Значение |
|---|---|---|
| **200** | `{ "ok": true }` | Конверсия принята в очередь |
| **400** | `invalid_click_id` | Пустой `click_id` |
| **400** | `invalid_status` | Нет/неизвестный `status` |
| **400** | `invalid_account_id` / `invalid_pwa_id` | Передан, но это не UUID |

#### Что происходит после приёма

1. Валидация → конверсия ставится в очередь, мгновенно возвращается `200`.
2. **Сразу** уходит исходящая отбивка (если настроена для этого PWA/события) — подробнее в разделе [Исходящие постбеки](builder.md#outgoing_postbacks).
3. Фоновый процесс находит исходный `Visit` по `click_id`, обогащает конверсию (гео, ОС, браузер, `account_id`, `pwa_id`) и пишет в статистику вместе с `cost`.
4. **Анти-фрод:** конверсия без соответствующего `Visit` в статистику **не попадает** (но отбивка при этом всё равно уходит, если резолвится `pwa_id` по домену).

### Исходящие постбэки {#outgoing_postbacks}

При помощи них вы уведомляете ваш трекер или партнерскую сеть о событиях по PWA.

#### Основные параметры

- Одна ссылка на пару (**PWA, событие**). На каждое нужное событие — своя строка.
- Отбивка настраивается **только на явное событие**. Отправки «на все события» (wildcard `*`) нет.
- Изменения применяются **сразу**, без перегенерации PWA.
- Повторное сохранение того же события **обновляет** ссылку.
- Переключатель **«включено»** позволяет временно отключить отбивку, не теряя URL.

#### Доступные события

| Событие | Когда срабатывает | Источник |
|---|---|---|
| `Visit` | показ блека | наш трекинг |
| `Install` | установка PWA | наш трекинг |
| `Open` | запуск PWA | наш трекинг |
| `PushSub` | подписка на пуши | наш трекинг |
| `Lead` | лид | постбек партнёрки |
| `Sale` | продажа | постбек партнёрки |
| `Reject` | отклонённая конверсия | постбек партнёрки |
| `Rebill` | повторное списание | постбек партнёрки |

!!! important "Важно" 
     `Visit` — высокочастотное событие, будет очень много исходящих запросов. Включайте осознанно.

#### Макросы в URL

В ссылку можно вставлять плейсхолдеры — при отправке мы подставим реальные значения:

| Макрос | Значение |
|---|---|
| `{click_id}` | Click ID посетителя |
| `{status}` / `{event_type}` | тип события (`Lead`, `Sale` и т.п.) |
| `{pwa_id}` | UUID PWA |
| `{account_id}` | UUID аккаунта |
| `{cost}` / `{payout}` | сумма конверсии (для lifecycle-событий обычно `0`) |
| `{timestamp}` | время события |
| `{stream_id}` | UUID потока — **только** lifecycle-события |
| `{country}` | страна (ISO-2) — **только** lifecycle-события |
| `{os}` | ОС — **только** lifecycle-события |
| `{browser}` | браузер — **только** lifecycle-события |

Пример: <https://domain.com/pb?cid={click_id}&status={status}&sum={cost}>

!!! note "Примечание"
    Вместо `status` также принимаются устаревшие `event` и `event_type`.Для конверсий (`Lead`/`Sale`/`Reject`/`Rebill`) отбивка уходит **в момент приёма `/event`** — гео/ОС/браузер/`stream_id` на этот момент ещё неизвестны, поэтому эти макросы **пустые**. Доступны: `{click_id} {status} {cost} {pwa_id} {timestamp}` + проброшенные параметры оффера. Для lifecycle-событий (`Visit`/`Install`/`Open`/…) заполнены все макросы.

#### Проброс параметров

Любые дополнительные параметры автоматически добавляются к вашей ссылке — прописывать их в шаблоне не обязательно. Ключи, заданные в шаблоне, приоритетнее одноимённых входящих. Откуда берутся:

- **Lifecycle-события** (`Visit`/`Install`/`Open`/`PushSub`) — из **параметров лендинга**: когда посетитель зашёл на PWA по ссылке `https://pwa.com/?sub_id=1&utm_source=fb`, эти параметры запоминаются и пробрасываются в отбивки по этим событиям.
- **Конверсии** (`Lead`/`Sale`/`Reject`/`Rebill`) — из параметров, которые прислал **оффер** в `/event` (`sub1`, `txid` и т.д.).

#### Доставка и повторные попытки

1. При событии сразу шлём **GET** на ваш URL (таймаут - 5 cекунд) — **попытка 1**.
2. Если ответ не `2xx` (или таймаут/ошибка сети) — ставим в очередь повторных попыток.
3. Фоновый сервис добивает: **всего 3 попытки, интервал 30 c**. Успех — при HTTP-коде **2xx** от вашего приёмника.

#### Пример сценария использования 

1. Посетитель заходит на <https://domain.com/?sub_id=fb_123>.
   Мы генерируем `click_id = a1b2c3` и запоминаем параметр `sub_id=fb_123`.
2. Событие `Install` → уходит отбивка (если настроена):
   <https://tracker.com/pb?cid=a1b2c3&sub_id=fb_123> (параметр лендинга проброшен).
3. Редиректим на оффер: <https://offer.com/?click_id=a1b2c3>.
4. Пользователь конвертит, партнёрская сеть или трекер присылает нам:
   `GET https://myapp.com/event?click_id=a1b2c3&status=Sale&cost=25&txid=T-99`
5. С нашей стороны:<br>
   - записываем `Sale` в статистику (нашли `Visit` по `a1b2c3`, добавили гео/ОС);<br>
   - отправляем **вашу** отбивку по `Sale`: <https://tracker.com/pb?cid=a1b2c3&status=Sale&sum=25&txid=T-99> (параметр оффера `txid` проброшен).

#### Ответы на частые вопросы 

**Отбивка не пришла на трекер.**<br>
Проверьте:<br> 
1. Отбивка на это событие создана и **включена**;<br>
2. URL отвечает `2xx` (3xx/4xx/5xx считаются неуспехом → уходят в ретраи);<br>
3. для конверсий — приходит ли к нам `/event` от партнёрки.

**Конверсия не видна в статистике, но отбивка ушла.**<br>
Это анти-фрод: конверсия без исходного `Visit` по `click_id` в статистику не попадает. Убедитесь, что партнёрка возвращает **наш** `click_id` без изменений.

**Нужно уведомлять сразу несколько трекеров.**<br>
Одна ссылка на пару (PWA, событие). Для мультикаста используйте промежуточный роутер постбэков на своей стороне.

**Что с суммой (`cost`/`payout`)?**<br>
Приходит из параметра `cost` в `/event`. В отбивке доступна как `{cost}` (алиас `{payout}`). Для lifecycle-событий обычно `0`.

## Клоакинг {#cloaking}

Клоакинг — это система фильтрации трафика, которая позволяет показывать разный контент разным пользователям. Модераторам рекламных сетей показывается вайт, а целевой аудитории — ваше PWA.

### Настройки параметров фильтрации {#settings}

**Шаг 1. Рекламная сеть**

Выберите источник трафика, под который нужно оптимизировать фильтрацию.<br>
Каждая сеть имеет свои особенности проверки — система учтёт это при фильтрации.

**Шаг 2. Страны**

Укажите географию вашего трафика:<br>
- **Разрешить** — только выбранные страны увидят PWA<br>
- **Запретить** — выбранные страны будут видеть вайт

!!! note "Примечание" 
     Пустое поле означает, что фильтрации по данному параметру не будет.

**Шаг 3. Операционные системы**

Укажите ОС устройства, которые будут попадать на PWA.<br>
Работает аналогично странам — можно разрешить или запретить.

!!! note "Примечание" 
     Пустое поле означает, что фильтрации по данному параметру не будет.

**Шаг 4. Браузеры**

Укажите браузеры, которые будут попадать на PWA.<br>
Работает аналогично странам — можно разрешить или запретить.

!!! note "Примечание" 
     Пустое поле означает, что фильтрации по данному параметру не будет.

### Настройка вайта {#safe_page}

Вайт — это страница с нейтральным контентом, которая показывается модераторам вместо вашего PWA.<br>
Доступны два способа для создания:

- **Из приложения** — система автоматически сгенерирует вайт на основе сслыки на приложение из Google Play
- **Из своего дизайна** — выберите настройки вайта самостоятельно

После настройки всех параметров нажмите **«Завершить создание»** — ваше PWA будет создано и станет доступно по указанному домену.

## Домен {#domain}

Для работы PWA необходимо привязать собственный домен. Привязка осуществляется через NS-серверы Cloudflare.

**Шаг 1. Привяжите домен**

В поле **«Домен»** введите ваше доменное имя без протокола и www (например: *example.com*)<br>
Нажмите кнопку **«Получить NS записи»** — система сгенерирует уникальные NS-серверы для вашего домена.

**Шаг 2. Укажите NS-серверы**

Вы получите два NS-сервера вида:

- NS1: **example.ns.cloudflare.com**<br>
- NS2: **example.ns.cloudflare.com**

Перейдите в панель управления вашего регистратора домена и замените текущие NS-серверы на указанные.

**Шаг 3. Проверьте привязку**

!!! important "Важно" 
     Изменения DNS могут занять от нескольких минут до 48 часов. Это зависит от вашего регистратора и текущего TTL записей.

После того как DNS-записи обновятся, нажмите кнопку **«Проверить привязку домена»**. Если всё настроено корректно, вы сможете перейти к следующему шагу.

**Типичные ошибки:**<br>
- Указан домен с www или протоколом — вводите только **domain.com**<br>
- NS-серверы ещё не применились — подождите и повторите проверку<br>
- У регистратора не сохранились изменения — проверьте настройки DNS
